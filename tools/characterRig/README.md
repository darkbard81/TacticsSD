# TacticsSD · Character Rig Studio

앞·뒷면 SD 캐릭터 이미지의 **6개 파츠를 지정하고 Rest / Idle / Walk와 등각 4방향을 실시간으로 확인하는 브라우저 에디터**입니다. [Issue #1](https://github.com/darkbard81/TacticsSD/issues/1)의 독립 실행형 MVP입니다.

![엘프 병사 원본과 리그 미리보기](docs/editor-initial.png)

## 실행

Node.js **24 이상**과 npm을 사용합니다. TypeScript 5.9.3, Vite 8.3.1, PixiJS 8.21.0을 잠금 파일로 고정했습니다.

```sh
npm ci
npm run tool
```

저장소 루트에서 실행합니다. 메인 주소는 기본 `http://localhost:5173`이며, **캐릭터 리깅 열기** 버튼으로 `/tools/characterRig/`에 진입합니다. 툴 헤더의 **메인으로** 버튼으로 돌아갑니다. 저장하지 않은 변경 사항이 있으면 기존 페이지 이탈 경고가 표시됩니다. 파일은 브라우저에서 로컬로 처리합니다. 별도 API 서버나 로그인은 필요하지 않습니다.

```sh
npm run build
npm run preview
```

빌드 결과는 `dist/`에 생성됩니다. 프로덕션 미리보기는 기본 `http://localhost:4173`입니다. 정적 호스팅 시 `dist/` 전체를 웹 루트에 배치합니다. 메인과 `tools/characterRig/index.html`이 각각 빌드됩니다.

## 작업 흐름

1. **기본 파츠 시트**로 시작하거나 **새 리그 → 이미지 불러오기**를 선택합니다. Front / Back 각각 PNG / WebP / JPG를 지정합니다. 한쪽만 있어도 편집됩니다. JPG의 배경은 자동 제거하지 않습니다.
2. 머리·몸통·양팔·양다리 중 선택합니다. ↖ 도구로 영역 이동, ▧ 도구로 새 사각형 지정, 모서리 핸들로 크기를 변경합니다. 속성의 수치 입력도 즉시 반영됩니다.
3. 금색 점을 드래그하거나 수치로 **부착점**을 조정합니다. 부착점은 잘라낸 영역 내부 픽셀 좌표입니다. L/R은 캐릭터 본인의 좌우이므로 정면의 왼팔은 화면 오른쪽입니다.
4. **부모 연결과 소켓**에서 몸통에 붙일 위치를 정합니다. 보라색 소켓은 원본 화면에서 드래그하거나 수치로 수정합니다. **접합 보정**은 연결 후의 위치·회전·배율을 조정합니다. 몸통을 움직이면 연결된 파츠가 함께 움직입니다. 숫자가 큰 파츠가 앞에 그려지며, 몸통을 숨겨도 자식은 표시됩니다. **배치 초기화**는 기본 시트의 소켓·기본 보정을 복원하고, 일반 리그에서는 소켓을 유지한 채 접합 보정을 초기화합니다.
5. **지면 X/Y, 기준 크기, 표시 배율**로 크기와 여백이 다른 Front/Back의 발밑과 표시 크기를 맞춥니다. Front 설정을 Back으로 비례 복사할 수 있지만, 후면에 맞게 수정해야 합니다.
6. Rest / Idle / Walk를 선택하고 재생·일시정지, 속도, 사이클 슬라이더를 사용합니다. **처음으로**는 재생을 멈추고 Rest / 0초로 돌아갑니다. 방향이나 뷰 변경은 현재 시간을 보존합니다.
7. Front / Back / SE / SW / NE / NW 또는 **4방향 비교**로 확인합니다. 속성에서 현재 방향의 이미지 계열, 반전, 보행 벡터, 좌우 모션 매핑, 팔 회전 부호 및 선택 파츠 위치·배율·skew·회전·순서를 수정합니다.
8. **리그 저장**으로 JSON을 내려받습니다. 이미지 파일도 보관하세요. 새 세션에서 JSON을 열면 하단의 **이미지 연결**로 원본/교체 이미지를 연결합니다. 파일명이 같으면 일괄 연결하고, 이름이 다르면 개별 연결합니다. 연결 시 크기를 검증합니다.

확대/축소는 휠 또는 ± 버튼, 화면 이동은 ✥ 또는 Alt+드래그, 선택 영역 이동은 방향키(Shift: 10px)입니다. 파일 버튼도 Tab 및 Enter/Space로 사용할 수 있습니다. 숫자 입력 오류는 현재 유효한 리그를 유지하며 알립니다.

동일 크기의 원본 이미지 교체는 영역을 유지합니다. **다른 크기로 교체하면 해당 뷰의 파츠 설정을 초기화**합니다. 잘못된 JSON이나 이미지 해석 실패는 현재 프로젝트를 보존합니다. 새 리그/샘플/정상 JSON 열기는 현재 프로젝트를 교체하므로 필요한 작업은 먼저 저장하세요. 페이지를 떠날 때 저장하지 않은 수정이 있으면 브라우저 경고가 표시됩니다.

## 기본 파츠 시트

제공된 JPG 1장에 정면·후면 머리와 몸통, 공용 팔 2개, 정면·후면 다리 4개가 들어 있습니다. 총 10개 영역으로 두 뷰의 6파츠를 구성합니다. 두 뷰는 이미지 한 장을 공유하고 영역·부착점·기준 배치·순서는 독립적으로 저장합니다.

- [기본 이미지](assets/elf-parts-sheet.png): 1254×1254 RGBA. 원본의 흰 배경을 이미지 편집 도구로 투명화한 파생 이미지입니다. 의상의 흰색과 파츠 외곽선은 유지했습니다. 생성 기반 편집으로 가장자리·세부가 원본과 조금 다를 수 있습니다.
- [기본 리그 JSON](assets/default-rig.json): 조립된 Rest 배치, 양발 지면 정렬, 모션 설정과 6방향 프리셋입니다.
- [원본 JPG 및 처리 기록](assets/source/elf-parts-sheet/README.md): 사용자 제공 원본을 그대로 보관합니다.
- **후면 전용 팔은 원본에 없어 공용 팔을 재사용**합니다. 후면 전용 팔 이미지가 있으면 파츠 교체로 적용할 수 있습니다.

프리셋의 재생성은 저장소 루트에서 `node tools/characterRig/scripts/create-default-rig.mjs`로 실행합니다. 이후 `npm run verify`로 검증합니다. 기존 생성 스탠디 `assets/elf-front.png`, `elf-back.png`와 생성 원본 `assets/source/elf-soldier/`는 이미지 교체 테스트와 비교 자료로 유지합니다.

## 새 에셋의 권장 규격

- 처음부터 분리된 **투명 RGBA PNG/WebP 시트**를 사용합니다. 완성 스탠디 절단과 JPG 배경 제거는 호환 입력입니다.
- Front/Back에 각각 `head`, `body`, `armL`, `armR`, `legL`, `legR`를 독립 제공하는 **12개 영역**을 권장합니다. 시트 1장에 모두 넣거나 뷰별 시트를 사용할 수 있습니다.
- 파츠 사이 투명 여백과 관절을 덮을 그림 여유를 둡니다. 시트의 사각형, 각 파츠 pivot, 몸통 소켓을 별도로 지정합니다.
- 현재 기본 시트의 공용 팔 재사용은 제공 원본을 유지하기 위한 예외입니다. 파츠 교체로 후면 전용 팔을 연결할 수 있습니다.

## 다른 이미지와 사각형 추출의 한계

다른 이미지나 **단일 이미지도 리깅할 수 있습니다**. 새 이미지의 초기 영역은 원본 전체를 겹침 없이 6개 사각형으로 나눕니다. 완성된 그림에서 팔·몸통이 붙어 있으면 같은 영역에 인접 부위가 포함되어 Walk 중 절단·틈이 보일 수 있습니다. 이 경우 영역과 배치를 수동 조정하거나 분리된 파츠를 사용하세요. 한 뷰만 불러오면 해당 뷰를 사용하는 방향만 표시되며, 뒷면이나 가려진 부분을 자동 생성하지 않습니다.

파츠별 **PNG / WebP / JPG 교체**도 가능합니다. 투명 PNG / WebP를 권장합니다. 이미지는 해당 파츠의 영역 크기에 맞춰 표시되고 같은 pivot/배치/모션을 사용합니다. 에디터는 배경 제거, 복잡한 마스크, 자동 분할, 인페인팅을 제공하지 않습니다. 분리 가능한 6색 테스트 원본에서 실제 Pixi 재조합 픽셀을 원본과 비교하는 별도 검증을 포함합니다.

등각 미리보기는 2D 반전과 파츠별 보정입니다. 실제 3D 회전이나 새로운 측면 그림을 만들지 않습니다. 비대칭 장비는 반전에 따라 좌우가 바뀝니다. 원하는 경우 3/4 원화로 교체하고 방향 프리셋을 조정하세요.

## 데이터와 좌표

- `domain/schema.ts`: 최신 `CharacterRigData` 형식, 템플릿, 검증. 과거 형식을 참조하지 않습니다.
- `domain/rig.ts`: 최신 리그 생성과 좌표·부모 연결 편집.
- `io/rig-file.ts`: 현재 버전의 파일 검증·읽기·저장. 버전이 다르면 변환 없이 거부합니다.
- `domain/default-rig.ts`: 기본 JSON 검증·복제, 파츠 시트 URL, 조립된 기본 배치 복원.
- `domain/animator.ts`: `evaluateRig`는 소켓 상대 모션, `evaluateWorldRig`는 계층을 합성한 지면 상대 행렬을 평가합니다. Pixi나 DOM에 의존하지 않습니다.
- `domain/transform.ts`: 순수 2D 행렬 합성·역변환. 부모 변경 시 방향 보정을 제외한 Rest 모습을 유지합니다.
- `runtime/renderer.ts`: `PixiRigRenderer`. 몸통 → 소켓 → 자식 pivot Container의 변형을 상속합니다. `RenderLayer`로 전체 파츠의 그리기 순서를 계층과 독립적으로 제어합니다.
- `runtime/assets.ts`: 로컬 이미지 디코딩, TextureSource 및 object URL 소유/해제, 누락 이미지 목록.
- `editor/source.ts`, `main.ts`: DOM/SVG 원본 편집과 DOM 속성 UI. 미리보기는 동일한 런타임을 사용합니다.

### pivot/socket 계층

```text
root (화면 배치·배율·방향 반전)
└ bodySocket (지면 상대)
  └ bodyNode (pivot·접합 보정·몸통 모션)
    ├ bodySprite
    ├ headSocket → headNode → Sprite
    ├ armLSocket → armLNode → Sprite
    ├ armRSocket → armRNode → Sprite
    ├ legLSocket → legLNode → Sprite
    └ legRSocket → legRNode → Sprite
```

| 필드 | 좌표와 역할 |
| --- | --- |
| `rect` | 시트에서 추출할 사각형. 위치를 바꿔도 접합 위치는 이동하지 않음 |
| `pivot` | 잘라낸 파츠 내부의 접합 기준점. 금색 점 |
| `attachment.parentId` | `body` 또는 `null`(지면). 몸통은 항상 지면에 연결 |
| `attachment.socket` | 부모 그림 좌상단 기준의 부착 좌표. 보라색 점. 부모가 없으면 지면 상대 좌표 |
| `restTransform` | 소켓에 연결한 뒤 적용하는 위치·회전·배율·skew 보정 |

합성은 `부모 행렬 × 소켓 이동 × (접합 보정 + 방향 + 모션, pivot 적용)`입니다. 몸통 이동·회전·배율·skew는 자식에게 상속됩니다. 몸통 바운스를 자식에 다시 더하지 않으며 머리 반동·팔 흔들림·다리 보행은 각 소켓 상대 모션입니다. 기본 등각 압축/skew도 몸통에 한 번만 적용합니다.

새 이미지의 최초 모습은 `rect 위치 + pivot - ground`에서 소켓을 계산해 보존합니다. pivot을 수정하면 그림의 위치가 유지되도록 접합 보정이 바뀝니다. 부모 소켓은 그림 좌표를 따르므로 몸통 pivot 변경 시에도 기존 접합이 유지됩니다. 지면 변경은 지면에 연결된 소켓만 이동시킵니다. 소켓은 외곽선이나 관절 여유를 위해 부모 사각형 바깥에도 둘 수 있습니다. DPR과 확대율은 저장 데이터에 포함하지 않습니다.

현재 부모 선택은 **몸통 또는 지면**입니다. 팔꿈치·무릎 체인이나 IK는 제공하지 않습니다. 부모 변경은 방향 보정 전의 Rest 모습을 보존하고, 방향 보정은 새 부모의 로컬 좌표에서 적용하므로 등각 화면은 다시 확인하세요.

### 개발 중 스키마 정책

현재 형식은 `schemaVersion: 2`, 파츠 ID는 `legL / legR`입니다. 외부 배포 전 개발 단계에서는 **리그 JSON의 하위 호환성을 보장하지 않으며 마이그레이션을 제공하지 않습니다.**

- 호환되지 않는 구조 변경 시 `CURRENT_SCHEMA_VERSION`을 올리고 이전 리그 파일은 폐기합니다. `schemaVersion`만 수동으로 바꿔 재사용하지 않습니다.
- 저장소의 기본 리그와 필요한 테스트 데이터는 현재 구조로 다시 생성합니다.
- v1 등 다른 버전의 파일은 오류와 함께 거부합니다. 자동 변환·묵시적 필드 보충·과거 스키마·호환 전용 실행 경로를 유지하지 않습니다.
- 파일 열기 실패 시 현재 리그와 연결 이미지를 유지합니다. 사용자는 **새 리그**에서 다시 작성합니다.
- 외부 배포와 파일 보존 요구가 생길 때 지원 버전 및 마이그레이션 정책을 다시 결정합니다.

모션 이동량은 뷰의 `referenceSize`에 대한 비율입니다. 표시 크기는 공통 가상 크기 1254에 정규화한 뒤 `displayScale`을 적용합니다. 방향 파츠 이동 보정은 1254 기준 단위입니다. 회전과 skew는 라디안입니다. root의 위치/배율/반전과 파츠의 Rest + 방향 + 모션 합성을 분리하며 프레임 간 변형을 누적하지 않습니다.

`SD_Walk` 한 사이클은 양발 각 한 번입니다. 접지에서는 전후 이동, 스윙에서는 복귀와 별도 발 들기를 적용합니다. 같은 쪽 팔은 발과 반대 위상입니다. 몸통 바운스는 한 사이클에 두 번입니다. 깊이는 들기와 별개이고 발끼리의 작은 순서 보정에만 사용합니다. 화면 Y로 전 파츠 순서를 재계산하지 않습니다. 발 크기 변화의 기본값은 0입니다.

JSON은 이미지 파일명/ID와 크기를 저장하고 이미지 바이너리, Pixi 객체, 일시적인 `blob:` URL은 포함하지 않습니다. Front/Back 원본, 교체 이미지, 모션/방향 설정을 모두 복원합니다. 거인은 동일 구조에서 비율과 모션 값을 바꿉니다. 다른 체형은 템플릿 레지스트리와 평가기 확장 지점만 준비되어 있으며 현재 지원은 Humanoid 6파츠입니다.

Linux에서 브라우저 시스템 패키지가 필요하면 `npx playwright install --with-deps chromium`을 사용합니다. `npm run verify`는 타입 검사·빌드·도메인·브라우저 테스트를 순서대로 실행합니다. **이 프로젝트에서는 이 로컬 결과를 CI 테스트 결과로 간주하며 GitHub Actions를 사용하지 않습니다.** `npm run test:all`은 도메인과 브라우저 테스트만 실행합니다.

[요구사항별 검증 기록](docs/validation.md)에서 테스트와 실제 샘플의 제약을 확인할 수 있습니다.
