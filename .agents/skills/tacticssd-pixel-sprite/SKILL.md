# TacticsSD Pixel Sprite Tool

`tools/pixel_sprite_tool/pixel_tool.py`는 Codex가 사용하는 파일 기반 제작 도구다. 24×32 RGBA 프레임을 프로젝트 JSON에 작성하고 PNG와 시트 메타데이터로 출력한다. 편집 가능한 원본은 프로젝트 JSON으로 유지한다.

새 캐릭터는 **ImageGen 원화 1장 → 픽셀 Base 완성 → 동작 프레임 제작 → 검수 → 시트 조립** 순서로 만든다. Base 한 장을 한 캐릭터 시트의 공통 기준으로 삼는다. 다른 제작 스킬을 참조하지 않고 ImageGen 도구와 이 저장소의 픽셀 도구를 사용한다. 기존 프레임 수정에서는 완성된 Base를 재사용한다.

## 준비와 명령

도구 문서는 [README](../../../tools/pixel_sprite_tool/README.md)를 읽는다. 기존 프로젝트와 사용자가 지정한 참고 이미지를 먼저 확인한다. 원화, 프로젝트 JSON, 편집 명령, 출력물은 작업별 디렉터리에 저장하고 기존 사용자 파일을 보존한다.

로컬 Python 환경과 Pillow가 준비되지 않았다면 한 번 실행한다.

```bash
npm run pixel-sprite:setup
```

로컬 환경을 선택하는 npm 래퍼로 실행한다.

```bash
npm run pixel-sprite -- new path/to/project.json --frames base
npm run pixel-sprite -- paint path/to/project.json base path/to/edits.json
npm run pixel-sprite -- clone path/to/project.json base walk_00
npm run pixel-sprite -- validate path/to/project.json
npm run pixel-sprite -- render path/to/project.json --out path/to/output --columns 4 --scale 16
```

`example.json`은 도구 실행을 확인하는 보석 예제이며 캐릭터 템플릿이 아니다. 덮어쓰지 않는다. 픽셀 편집은 `[x, y, paletteSymbol]` 배열을 담은 JSON과 `paint`, 또는 도구의 Python API로 수행한다. `clone`은 독립적인 프레임을 만들며, 복제 뒤에는 실제 자세를 편집해야 한다.

## 제작 기준과 순서

### 1. 기준 프레임부터 완성

정면이나 대표 자세 한 장에서 비율·의상·팔레트를 확정한 뒤 다른 프레임으로 확장한다. 새 캐릭터는 투명 배경 ImageGen 원화를 먼저 생성하고 파일로 보존한다. 프레임마다 별개의 캐릭터 원화를 생성하지 않는다.

2등신 SD 요청에서는 **원화부터 머리가 전체 키의 약 절반**을 차지하도록 한다. 긴 몸의 원화를 축소하는 것으로 2등신을 대신하지 않는다. 유리아·택틱스 오우거 참고 요청이 있으면 `docs/Ref/sprite/`의 해당 시트를 직접 열어 머리와 몸의 비율, 방향 표현, 작은 크기에서 읽히는 의상 덩어리를 확인한다.

원화를 최초 픽셀 Base로 옮길 때만 캐릭터 영역 자르기, 셀 안에 맞추기, 투명도 정리, 팔레트 축소를 수행한다. 자동 축소 결과는 초안이며 눈·귀·손·의상 경계를 픽셀 단위로 정리한다. 완성된 Base를 원본 크기와 확대 이미지로 확인하기 전에는 동작 프레임을 늘리지 않는다.

### 2. 실루엣을 먼저 잡기

내부 명암을 넣기 전에 불투명 픽셀을 한 색으로 표시해 확인한다. 단색에서도 머리·몸·팔·장비나 무기, 바라보는 방향이 구분되어야 한다. 팔과 몸, 양다리 사이의 여백과 외곽선을 확보한다. 읽히지 않는 부위는 색을 늘리기 전에 형태와 배치를 수정한다.

### 3. 색과 명암을 단순하게

공통 팔레트는 불투명 색 **8~16색 정도**로 시작한다. 투명 심볼 `.`은 별도로 두고 RGBA `[0, 0, 0, 0]`을 사용한다. 피부·머리카락·천·금속 등 재질별 기본색·그림자·밝은색 역할을 정하고, 가능한 색은 공유한다. 같은 재질은 모든 프레임에서 같은 색을 사용한다.

색 수를 늘리기 전에 기존 색과 덩어리 배치로 해결한다. 사용자 지정 팔레트가 있으면 우선하며, 추가 색이 필요한 경우 용도를 기록한다. 축소 과정에서 생긴 중간색이나 반투명 가장자리를 그대로 최종 팔레트로 채택하지 않는다.

### 4. 픽셀을 덩어리로 배치

그림자와 밝은 부분을 연결된 면으로 만든다. 외곽선의 계단 간격과 굵기를 정리하고, 의미 없는 점·구멍·잡색을 제거한다. 고립된 1픽셀은 눈·작은 장식·반짝임처럼 의미가 있는 곳에 사용한다. 기계적인 디더링이나 노이즈로 작은 캐릭터의 형태를 흐리지 않는다.

### 5. 프레임마다 기준 유지

셀 크기 24×32, 머리와 몸통 크기, 몸 중심, 발이 닿는 기준선, 공통 anchor를 Base에서 정하고 기록한다. 기존 프로젝트에서는 팔레트·anchor·순서·재생 시간을 유지하며 필요한 부분만 수정한다. 도구 기본 anchor는 `[12, 31]`이며 기존 작업의 다른 공통 anchor도 유지할 수 있다.

Base 완성 뒤에는 프레임별 자동 자르기·확대 축소·중앙 정렬·보간을 하지 않는다. 걷기의 상하 움직임이나 기울기는 의도한 픽셀 이동으로 작성하고, 지지하는 발과 몸의 관계를 확인한다. 캔버스와 anchor는 고정한다. 포즈가 셀 밖으로 잘리면 먼저 실루엣과 배치를 조정하고, 해결되지 않는 도구의 크기 제한은 명시한다.

### 6. 핵심 자세부터 움직임 만들기

사용자가 요청한 동작과 방향만 제작한다. 걷기는 발이 벌어진 접지 자세와 다리가 교차하는 자세 등 동작을 설명하는 핵심 자세부터 만든다. 공격을 요청받았다면 준비·타격·회복 등 핵심 자세부터 만든 뒤 필요한 연결 프레임을 추가한다.

팔다리의 이동과 함께 골반·몸통의 체중 이동, 지지하는 발, 팔과 다리의 교차 움직임을 표현한다. 발끝 몇 픽셀 이동이나 전체 이미지 평행 이동만으로 완성된 걷기로 간주하지 않는다. 작은 크기에서도 핵심 자세끼리 구분되고, 의상·얼굴·장비의 정체성이 유지되어야 한다. 재생 시간은 동작의 속도와 무게에 맞춰 지정한다.

### 7. 원본 크기·확대·재생으로 확인

`validate` 후 전용 검수 디렉터리에 `render`한다. 다음 세 가지를 모두 확인한다.

- **원본 크기:** 24×32에서 캐릭터, 방향, 동작이 읽히는지 확인한다.
- **확대:** nearest-neighbor 확대, 단색 실루엣, `review/`의 grid/zoom 이미지와 `contact.png`를 직접 열어 픽셀 연결·팔레트·불필요한 점·기준선·크기 일관성을 확인한다.
- **재생:** 실제 프레임 순서와 `duration_ms`로 반복 재생하여 팔다리 궤적, 체중 이동, 발 미끄러짐, 마지막→첫 프레임 연결을 확인한다.

CLI는 정적 PNG와 JSON을 출력하며 재생 미리보기를 제공하지 않는다. 필요하면 내보낸 프레임과 재생 시간으로 로컬 애니메이션 미리보기를 만들어 재생한다. 정적 contact sheet 확인을 재생 검수로 보고하지 않는다. 재생을 확인하지 못했다면 그 항목은 미검증으로 명시한다.

수정은 원본 프로젝트 JSON에 반영하고 다시 렌더링하여 해당 항목을 재검사한다. 명령 성공만으로 시각 검수를 완료했다고 판단하지 않는다.

### 8. 완성된 프레임을 시트로 조립

중간 렌더는 검수용으로 사용하고, 검수가 끝난 프레임을 최종 시트에 배치한다. 셀 크기·공통 기준점·투명 배경을 유지하며 동작과 방향별 순서를 일정하게 정한다. 사용자가 지정한 순서가 있으면 그대로 따른다. 행·열 배치와 반복 구간을 명시하고 프로젝트의 프레임 배열 순서와 일치시킨다.

`render --columns N`으로 조립하며 `--scale`은 검수용 확대 배율이다. 실제 프레임은 24×32, 시트 padding은 0이다. `spritesheet.json`의 프레임 좌표·크기·순서·재생 시간·anchor가 PNG와 일치하는지 확인한다. 최종 PNG의 크기, RGBA 모드, 투명 픽셀 존재와 가장자리 잘림도 검사한다.

## 결과 보고

원화(새로 생성한 경우), 편집 가능한 프로젝트 JSON, 최종 `spritesheet.png`와 `spritesheet.json`, 검수 또는 재생 미리보기 경로를 제공한다. 프레임 크기·개수·배치 순서와 실제로 수행한 검수, 남은 제한을 짧게 보고한다. 이 도구 자체는 원화 생성이나 시각 검수를 수행하지 않는다.
