# 원정 보급소 · 1차 구현

2026-10-04. 사용자의 후속 승인 “상점 구현시작”, “아이템목록은 pdf와 url을 참조하고 각 아이템 이미지도 작성”에 따라 구현했다. 실제 결제·배포는 없다.

## 범위와 출처

- 원문 1,170개 고유 sourceID = weapons 445 + armor 172 + sundries 553. 원문에는 선천 공격·아르카나·클래스마크·재료·제작서도 있으므로 모두 판매품으로 취급하지 않는다.
- 런타임 등록 **44개 = 원문 기반28개 + 창작16개**. 원문28개는 활3·방어구/장신구20·회복품5. 기존 Mend Leaf를 통합하고5슬롯에 맞지 않는 바지류는 제외했다. 원문 미등록1,142개는 도감에서 참고 전용·구매불가로 표시한다. 전체 카탈로그를 구현했다고 주장하지 않는다.
- [원본 스냅샷/해시](reference/SOURCE_MANIFEST.json), [실제 등록 목록](reference/REGISTERED_ITEMS.json), `game/source-items.json`에 sourceID·원문 이름·URL·원본 타입·가격·레벨·eq 직업플래그·원본 효과·게임 적용값을 각각 보존했다. `game/source-catalog.json`은1170행의 등록상태/미등록 사유를 담는다.
- 공식 PSP 전투와 OV 아이템 데이터는 다른 층이다. URL은 [무기](https://ogre-db.github.io/one-vision/weapons.html), [방어구](https://ogre-db.github.io/one-vision/armor.html), [기타](https://ogre-db.github.io/one-vision/sundries.html)의 현재 JSON 표를 사용했다. PDF [Readme v1.11d.pdf](reference/readme-v1.11d.pdf)는 과거 패치 이력과 비교했다. 직접 품목명이 없는 페이지 번호를 지어내지 않았다.
- PDF p62는 War Bow/Shortbow 진행 순서 교환, p77–78은 Ginseng의50TP 추가/입수시기, p115는 과거 Mend Leaf50HP/Mending Seed150HP/Mending Salve50%와 당시 가격을 설명한다. 현재 URL은 Seed100+최대HP15%, Salve150+20%이므로 과거 PDF값과 혼합하지 않는다. Leather Gloves p88은 후속 장갑 비교 문맥이고 개별 현재 수치의 근거는 URL이다.

## 적용 규칙과 생략

게임 가격=원문 가격÷10 올림, 판매가격=게임 구매가÷2 내림. 소규모 캠페인 수치 보정: STR/VIT/DEX/AGI/AVD/INT/MND/RES÷4(절댓값 올림), DEF÷6 올림, 무기ATK÷8 올림, 기타장비ATK÷4 올림, HP/MP÷4 올림, 물리저항÷5 올림. 기존 창작 장비는 원래 값을 유지한다. 장신구의ATK도 실제 합산한다. sourceItems에 원값과 적용값이 함께 있다.

원문 Lv>5 품목은 게임에서 첫 거점 해방 후 입고한다. 원작 직업/레벨 제한의 정확한 이식이 아니다. 방어구는6대원 공용, 활은궁수용이다. 원문 활의 min/maxrange·무게·개별RT·양손/방패 충돌·원소/종족저항·방패공격·제작식은 현재 적용하지 않는다. 게임 활 사거리는4, 공격RT는기존 공통규칙이다. UI에도 수치축소와 주요 미지원 효과를 표시한다.

5회복품은 URL effect265/269/273/277/279의 기본값+최대치%를 적용한다. HP50+10%, HP100+15%, HP150+20%, MP20+5%, TP50. 정수화 후 대상의 결손량으로 제한한다. HUD 예측과 `act`가 같은`damage` 경로를 쓴다. 창작 MP/TP물은12회복을 유지한다. 모든 회복품은 현재 게임 사거리2다.

## 거래·재고·저장

`game/shop.ts`의 상품 레지스트리와 순수 거래 후보 함수를 사용한다. 수량1–99 정수, 보유999, 자금99,999G 한도. 대기대원 포함 장착 수량은 판매불가다. 원본 미등록품·부족한 자금·잠긴 품목·잘못된 수량/ID는 거래하지 않는다. 확인 화면은 취소에 먼저 포커스한다. 확정 시 후보를 저장한 뒤 현재 상태를 바꾸므로 저장오류는 자금/재고를 원복할 필요 없이 유지한다. pendingQuote를 먼저 비워 중복확정을 방지한다. 확인+취소 동시입력은 취소 우선, 패드해제/창비활성화는 거래확인을 닫는다.

구버전 v1/v2의 inventory 없는 저장은 기존 선택가능 장비를 유한 시작 창고로 이행한다(기본/여명 무기는 사용대원 수, 방어구/기존 추가장비는6개씩). 기본 보급은 Leaf3/MP물1/TP물1. 상점이나 전투승리 후 inventory를 stable itemID로 저장한다. 장착품보다 적은 재고/미등록ID/잘못된 수량 저장은 거부한다. 전투는 출전 전 체크포인트이며 승리 시 실제 남은 보급을 저장한다. 패배/재시작은 출전 전 재고로 복원한다. 완료전투 재방문은 첫승리보상을 중복 지급하지 않는다.
